# 产品资产完整性检查设计

## 目标

在构建和发布前确认 `data/products.json` 中引用的本地产品图片真实存在，并对 `public/images/products` 中尚未登记的 `0921*.png` 图片给出可见告警，避免漏图或误删素材。

## 范围与约束

- 新增跨平台 Node 检查脚本，不引入新依赖。
- 只把缺失的本地引用视为失败。
- 未登记的 `0921*.png` 只告警，不删除、不移动、不改名、不自动写入产品数据。
- `http://`、`https://` 等外部图片引用不按本地文件检查，但应在报告中计数。
- 解析路径必须限制在 `public` 目录内，拒绝路径穿越。

## 设计

新增 `scripts/verify-assets.mjs`，提供命令行入口和可测试的纯函数：

- 从产品 JSON 递归收集键名为 `image` 或 `images` 的字符串路径。
- 对以 `/` 开头的引用解析到 `public` 下并检查文件存在性。
- 对外部 URL跳过本地存在性检查并统计。
- 扫描 `public/images/products/0921*.png`，输出未被产品 JSON 引用的文件名。
- 缺失引用或非法本地路径返回退出码 `1`；未登记文件仅返回退出码 `0`。

在 `package.json` 增加 `verify:assets`，并在 CI 构建前运行。报告必须包含引用总数、缺失数、外部引用数和未登记批次数量，便于发布前人工决定是否登记图片。

## 验证

- 用临时目录测试：存在引用通过、缺失引用失败、外部 URL 不误报、路径穿越失败、未登记图片只告警。
- 在当前仓库运行真实资产检查，确认现有图片未被修改且 56 张 `0921*.png` 不会导致 CI 失败。
- 与完整 Vitest、Lint、类型检查和生产构建一起验证。

## 明确不做

- 不转换 WebP/AVIF，不改变图片质量或文件名。
- 不自动注册商品，不删除未登记图片，不接入对象存储或 CDN。
